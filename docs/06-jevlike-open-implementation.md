# 06. 오픈소스 구현 해부 — jevlike

> [vinnylarouge/jevlike](https://github.com/vinnylarouge/jevlike) —
> Jev와 **같은 입출력 형태**를 내는 독립 오픈소스 스타터 모델.
> TypeSafe가 Jev의 설계를 공개하지 않았기 때문에, 이건 재현이 아니라
> "같은 계약(contract)을 만족하는 작은 모델을 직접 만들면 어떤 모양이
> 되는가"를 보여주는 레퍼런스다. 저자도 명시적으로
> *"Jev와 동등한 품질을 보였거나 TypeSafe의 비공개 학습법을 재현한 게
> 아님"* 을 밝힌다. (발표 직후 1.1k 스타)

## 계약이 같다는 것의 의미

Jev의 Choice 질의와 jevlike의 추론은 모양이 같다:

```
입력:  context (텍스트) + options (선택지 N개)
출력:  선택지별 확률 N개 (합 = 1) — 토큰 생성 없이 한 패스로
```

LLM으로 이걸 하면 "답을 문장으로 써달라 → 파싱"이 되지만,
이 계약에서는 애초에 **답이 선택지 인덱스 하나**로 결정되어 있다.
출력 공간이 N으로 갇히니 자기회귀 생성이 필요 없어지고,
원패스가 된다 — 이게 [02](02-how-it-works.md)에서 본
"병렬 샘플링"의 구조적 이유다.

## 옵션-어텐션 아키텍처

jevlike의 핵심은 `AttentionHead` 하나다. 흐름:

```
 context 토큰들                선택지 N개
 ┌─┬─┬─┬─┬─┐                ┌──┬──┬──┐
 │ │ │ │ │ │                │o₁│o₂│o₃│
 └─┴─┴─┴─┴─┘                └┬─┴┬─┴┬─┘
      │ key/value 프로젝션        │ query 프로젝션
      ▼                          ▼
   K, V 벡터들               Q₁  Q₂  Q₃      ← "각 선택지가 query가 된다"
      └──────────┬─────────────┘
                 ▼
   어텐션: Qᵢ가 context 토큰들을 바라봄 → 선택지별 맥락 벡터 Aᵢ
                 ▼
   점수: sᵢ = Qᵢ · Aᵢ / √rank      ← 선택지 하나에 스코어 하나
                 ▼
   softmax(s₁..sN)                 ← 선택지 **전체에 걸쳐** 정규화
                 ▼
   확률 p₁..pN (한 번의 순전파로 전부 계산)
```

이 모양이 아름다운 이유 세 가지:

1. **선택지마다 query** — "이 선택지에 맞는 증거를 context에서 골라봐"라는
   질문이 어텐션 구조 그 자체다. 선택지가 늘어나면 query만 늘면 되고
   context 인코딩은 공유된다.
2. **softmax가 선택지 축** — LLM이 토큰 축에서 softmax를 돌리는 것과
   달리, 여기는 선택지 N개 사이에서만 확률이 된다. 타입 안전성의
   신경망 버전: 가능한 답이 정의되지 않은 게 원천적으로 없다.
3. **순서가 없다** — 토큰을 순서대로 뽑는 게 아니라 모든 sᵢ가 동시에
   나온다. 출력 토큰 비용이 0인 이유.

인코더는 두 가지 경로를 제공한다:

| 경로 | 구성 | 특징 |
| --- | --- | --- |
| `TinyScorer` | 바이트 임베딩(257 어휘) + 위치 임베딩을 **처음부터 학습** | 진짜 from-scratch. context 192바이트 / 선택지 32바이트 |
| `FrozenTransformerScorer` | HF 사전학습 인코더(예: Qwen2.5-0.5B)를 **동결**하고 head만 학습 | 지능은 빌리고 판단 구조만 학습 |

둘 다 "학습되는 것은 어텐션 head뿐 또는 대부분"이라는 점에서 같다 —
Jev가 주장하는 "작은 LLM이 아니다"와 맞닿아 있는 설계 감각.

## 훔길 만한 평가 방법론

jevlike의 `eval`이 찍는 지표가 이 스터디의 보완 포인트였다:

1. **top-1 / top-3 정확도** — 1등이 맞았는가 / 상위 3에 정답이 있는가
2. **ECE (Expected Calibration Error)** — 보정 오차의 요약치.
   신뢰도 버킷의 |확신 − 실제 적중률| gap을 버킷 크기로 가중 평균.
   → 이 레포 `calibration.ts`에 `ece()`로 추가했다.
3. **셔플드 컨텍스트 컨트롤** — 같은 배치에서 context를 한 칸씩
   밀어(cfg. `context.roll(1)`) 모든 질문에 **엉뚱한 맥락**을 짝지운다.
   모델이 뭔가 학습했다면 정상 짝보다 컨트롤에서 성적이 뚝 떨어져야
   한다. "데이터 외우기"와 "진짜 판단"을 가르는 값싼 시험.
   → 목업에도 같은 관찰을 테스트로 남겼다 (`tests/client.test.ts`).

이 컨트롤 발상은 LLM 평가에도 그대로 쓸 수 있다 —
"질문과 맥락을 뒤섞은 베이스라인을 이기는가"는 어떤 판단 모델에도
의미 있는 최소 관문이다.

## 저자가 보고한 숫자 (로컬 실험)

| 실험 | 결과 |
| --- | --- |
| 합성 데이터 메뉴 선택 | top-1 ≈ 98% |
| Wikispeedia "다음 클릭" (대상 페이지 분할, frozen Qwen 인코더) | 26% — 셔플/랜덤 인코더 컨트롤 ≈ 8% |
| 같은 데이터, 4만 클릭으로 from-scratch | 29% |
| 선택지 8개 기준, 소형 디코더가 400토큰 쓰는 것과 비교 | **약 100배 빠름** (원패스) |

마지막 숫자가 흥미로운 이유: TypeSafe의 "40~200배 빠름"은 벤더
셀프 리포트인데, 제3자의 독립 구현에서도 같은 자릿수가 나왔다.
원패스 구조의 속도 이점 자체는 마케팅이 아니라 구조의 성질인 셈.

## 같은 head로 게임을 한다 — vision 확장

재미있는 사실: 이 옵션-어텐션 head는 텍스트가 아니라 **이미지 패치**에도
그대로 붙는다. jevlike는 이걸로

- **Doom 컨트롤러** — 게임 화면 패치를 context 삼아 7개 버튼 중 하나를
  프레임마다 선택
- **체스 컨트롤러** — 보드 이미지에서 5개 키 선택

를 돌린다. "비정형 state(텍스트든 이미지든) + 정의된 행동 집합 →
행동별 확률"이라는 Jev의 계약이 시각 도메인으로 자연 확장되는
시연이다. TypeSafe 공식 데모의 Doom 봇이 "아직은 이미지가 아니라
구조화된 텍스트 상태"라고 못 박았던 것과 대비되는 지점.

## 이 문서의 결론

- Jev의 **계약**(입출력 형태)은 재현 가능하고, 이미 재현됐다 —
  그 결과물이 선택지 축 softmax를 가진 원패스 스코어러다
- 하지만 **품질**(프론티어 지능, 보정 수준)은 TypeSafe의 비공학습
  데이터/RLCD에 있을 것 — 저자도 동등 품질을 주장하지 않는다
- 즉 "Jev는 마법이 아니라 (1) 좁은 출력 계약 + (2) 원패스 구조 +
  (3) 보정 학습의 조합"이라는 이 스터디의 가설에 대한
  독립적 정황 증거
